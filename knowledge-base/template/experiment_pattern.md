# 比較・検証 Pattern

## 結論
何を比較・検証し、現時点でどう判断するかを簡潔に記述する。

## 目的
何を判断するための比較・検証か。
検証によって答えたい問いを明確にする。

## 仮説
事前に想定していた結果がある場合に記述する。
なければ省略してよい。

## 環境
結果に影響する条件だけを書く。

- CPU:
- GPU:
- RAM:
- OS:
- ソフトウェア / バージョン:
- 設定:
- その他:

## 比較条件
比較対象以外で揃えた条件を記述する。
揃えられなかった条件がある場合は明示する。

## 結果

| 方法 / 条件 | 結果 | 備考 |
|---|---:|---|
| A | ... | |
| B | ... | |

必要に応じて、生データや詳細ログは Raw 側へ置く。

## 観察
結果から直接読み取れることを書く。
推測や原因説明とは分ける。

## 解釈
なぜその結果になったと考えるか。
未確認の説明は仮説として扱う。

## 判断
今回の条件では、どの方式・設定を採用するか。
判断しない場合は、その理由を書く。

## 適用範囲
この結論をどこまで適用できるか。

例:
- 特定 GPU / RAM 構成のみ
- 特定バージョンのみ
- 短い入力のみ
- 特定データ量まで

## 再検証条件
どの条件が変わったら再度測定すべきか。

例:
- ハードウェア変更
- ソフトウェア更新
- データ量増加
- 実装変更
- 前提条件変更

## 根拠
Raw、ログ、測定結果、ベンチマーク出力など。

## 関連
関連する Pattern、Raw、設計判断など。
