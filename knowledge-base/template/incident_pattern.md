# 障害・調査 Pattern

## 結論
原因と、次回同じ症状が出たときに取るべき対応を簡潔に記述する。

## 症状
実際に何が起きたか。
観測した事実だけを書く。

## 発生条件
再現に関係する条件を書く。

- OS / 実行環境:
- ハードウェア:
- ソフトウェア / バージョン:
- 設定:
- 再現手順:
- その他:

## 原因
確認できた原因を記述する。

原因が未確定の場合は、仮説であることを明示する。

## 調査
原因特定に重要だった調査だけを残す。

### 有効だった確認
- 確認内容:
  - 結果:
  - 何が分かったか:

### 失敗・無効だった方法
将来また試してしまいそうなものだけ残す。

- 方法:
  - 結果:
  - 無効だった理由:

## 解決策
実際に有効だった手順や設定変更を記述する。

## 回避策
根本解決できない場合の運用上の回避策があれば記述する。

## 再発防止
次回同じ問題に遭遇したとき、調査を短縮するための判断基準を書く。

## 適用範囲
この原因・対策が成立する環境や条件を記述する。

## 再検討条件
次のような条件で再調査が必要なら記述する。

- バージョン更新
- OS / ドライバ変更
- ハードウェア変更
- upstream 修正

## 根拠
ログ、エラーメッセージ、Raw、Issue、実測など。

## 関連
関連する Pattern、Raw、設定、Issue など。
